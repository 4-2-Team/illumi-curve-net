What changed since report 2

Report 2 showed masking the exposure loss made it too easy to satisfy, and the optimizer spent the freed-up budget wrecking spatial/texture fidelity instead. The weights were rebalanced accordingly (still with the masked exposure loss and synthetic-degradation training from report 2, unchanged):

L_color 5.0 → 3.0 (already trivially satisfied)
L_spa 1.5 → 3.0 (was being sacrificed)
L_exp 10.0 → 6.0 (easier objective now it's masked)
L_TV 200.0 → 50.0 (near-zero already, wasted weight)
L_contrast 5.0 → 5.0 (unchanged, was stable)
L_texture 3.0 → 6.0 (was being sacrificed)

The hypothesis: giving L_spa/L_texture more weight and L_TV less should stop the trade-off that hurt report 2, without giving up the gains masking the exposure loss made possible. That's exactly what happened — see below.

Findings & caveats

  • ✓Rebalancing fixed report 2's regression completely, and then some. V3 beats the pretrained baseline, report 1's v1, and report 2's v2 on every IQA metric measured (NIQE, BRISQUE, PIQE) on the actual 318-image test set — PIQE 19.3 is even better than the untouched baseline's 20.4. This is the model to use going forward: snapshots/model-best-v3_rebalanced.pth.
  • ✓The mechanism matches the hypothesis exactly. L_texture dropped 73% and L_spa dropped 69% relative to v2 — instead of being sacrificed for exposure gains, they're now both better than baseline too. L_exp still fell 91% vs. baseline (masking plus a lower weight was enough) without the side effects report 2 saw.
  • •L_TV rose off its near-zero floor (0.0006→0.0011) as expected from cutting its weight 200→50 — still negligible in absolute terms, and clearly a good trade for what the other terms gained.
  • ✗Genuinely low-light input remains unsolved. On synthetically degraded test images, V3 improves over v2 (BRISQUE −5.7%, PIQE −1.8%) but is still worse than simply running the untouched baseline on the same degraded input (BRISQUE +23.8%, PIQE +9.4%). Across all three fine-tuned variants, none has beaten the baseline at handling real noise — the synthetic degradation recipe (gamma+exposure+noise) may not resemble real sensor low-light noise closely enough, or the model needs an explicit denoising term to avoid amplifying it.
  • •Recommended next step, if low-light robustness matters for deployment: treat it as a separate track from this one — validate the synthetic degradation against real dim lunar photos if any exist, or add a noise-aware loss term, rather than folding it into further weight tuning on the current recipe.
